# Grounded coaching — design contract v1

Coaching explains a specific completed saved run/half-move; it never classifies a mistake or creates chess evidence. Source history, FEN, played/best moves, exact legal search lines, score perspectives, completed/non-provisional state, engine settings and snapshotted classifications must agree before an explanation is eligible. A finite engine search and output validation are not proof of complete chess understanding.

The selected beginner/intermediate/advanced level always controls the explanation. Known public provider/pool ratings can adjust line length **within** that level: the presentation bands are Chess.com below 1000 / 1000–1599 / at least 1600 and Lichess below 1300 / 1300–1899 / at least 1900. These are presentation heuristics, not rating conversions or calibrated skill labels. An absent rating or unknown pool uses the selected level's default. PGN ratings with no supported pool stay labelled as recorded PGN ratings and do not change depth. Provider, pool and exact time control remain separate in saved provenance.

Factual explanations provide what happened, why the verified result mattered, a better legal continuation and one reusable practice lesson. Beginner language emphasizes threats and short lines; intermediate language emphasizes calculation and candidate comparison; advanced language retains longer checked lines and defence testing. Named forks, pins and skewers are unavailable until a separate legal motif proof exists. The supported generic tactical-opportunity or forced-mate labels can be used when the saved evidence establishes them.

An optional model selects emphasis from a server-created registry of verified factual statements and general lessons. Its structured response must echo the exact evidence hash and level, reference only registry fact/lesson IDs, and provide a prefix of the supplied legal best continuation. All required explanatory sections must remain present. Unsupported facts, invented motifs, extra fields, unrelated evidence, changed moves, malformed/incomplete/refused responses and stale evidence are rejected. Free-form model claims are not displayed. The interface labels factual templates separately from model-selected explanations; the model's constrained role is disclosed rather than presented as unrestricted chess expertise.

The [OpenAI Responses structured-output contract](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) was checked on 13 October 2026. The provider is an implementation of a server interface, not a dependency of the core coaching loop. No usernames, PGN comments, raw PGNs, emails or imported prose are sent to it. API secrets remain server-side; fixed provider endpoints, request/input/output deadlines and sizes, compatible cache keys, durable attempt limits, global/per-owner request and conservative reserved-cost budgets apply. Defaults disable paid requests. Enabling optional requests requires explicit server configuration and user opt-in. Provider failures, absent credentials/budgets and interrupted requests use factual coaching.

## Limits and configuration

`Coaching:Enabled` defaults to false. `Coaching:ApiKey`, `Model`, positive owner/global micro-dollar budgets and positive input/output micro-dollar-per-token ceilings are required before an opted-in account can make an optional request. No model or price is selected automatically. Configure both API and worker consistently through server environment variables or mounted secrets. Operators must verify ceilings against the selected model's current official price and use the provider account's own spending controls. Reserved cost is conservative accounting, not a claim to reproduce a provider bill.

Defaults permit at most 20 model requests per owner and 100 globally per rolling day, with 300 new cached coaching positions per owner/day and three active optional explanations. Each request reserves 32,768 input bytes as an upper token bound plus at most 512 output tokens (configurable 128–1024), at the operator's ceilings. Requests have a ten-second deadline (configurable 1–20 seconds), a 64 KB response bound, no tools and `store:false`. An explanation attempts the model at most once. A reservation commits before submission and is never refunded on cancellation, timeout, failure or imported-data deletion; interrupted delivery falls back on factual coaching instead of sending a second request. The retained usage ledger contains only account/job references, time and budget numbers. Explanation/evidence records themselves cascade with imported data.

Database locks serialize provider work globally and budget reservations globally/per owner. Explanations retain exact run/ply/FEN, evidence hash, selected level, rating context, legal line, facts/lessons, prompt version, requested model ID, returned model/provider ID and provider response ID. Even an unsupported model plan retains its returned provenance while displaying factual coaching. Cache identity includes evidence, level and optional-provider configuration. Cancelled/failed explanations can be reopened as factual coaching; a late model result cannot revive a cancelled/deleted job. No-key factual results are immediately available without a worker or external service. Optional jobs use one-minute leases and three durable recovery attempts; paid delivery remains at-most-once across recovery.

Tests use clearly labelled model doubles and HTTP contract fixtures; actual no-key Stockfish/browser journeys are separate evidence. No paid live model call has been authorized or made. See the acceptance matrix and verification ledger for demonstrated status and limitations.
